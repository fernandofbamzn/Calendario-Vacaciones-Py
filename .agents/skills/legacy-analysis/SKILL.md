# Skill: Legacy Analysis

## Usar cuando

- Se abra un proyecto antiguo.
- Se desconozca la arquitectura.
- Se quiera preparar una migración.
- Haya código con mucha lógica mezclada.

## Proceso

1. Identificar tipo de aplicación.
2. Localizar puntos de entrada.
3. Detectar módulos críticos.
4. Separar UI, negocio, datos e infraestructura.
5. Identificar dependencias externas.
6. Revisar cómo se gestionan errores.
7. Revisar si existen logs.
8. Detectar riesgos de migración.
9. Proponer fases de trabajo.

## Resultado

Entregar:

- Mapa del proyecto.
- Riesgos principales.
- Módulos candidatos a refactor.
- Módulos que conviene no tocar inicialmente.
- Plan incremental.
