# Documentation Rules

## Principios

- Documenta decisiones, no obviedades.
- Mantén documentación cercana al código cuando sea útil.
- Usa castellano salvo convención explícita del proyecto.
- Los README deben explicar cómo ejecutar, configurar, probar y desplegar.

## Documentación técnica mínima

Para proyectos serios, debe existir documentación sobre:

- Objetivo del proyecto.
- Requisitos.
- Configuración.
- Ejecución local.
- Build.
- Tests.
- Despliegue.
- Logging.
- Gestión de errores.
- Dependencias externas.

## Cambios importantes

Cuando una tarea cambie arquitectura, base de datos o despliegue, actualiza documentación o deja una nota clara de documentación pendiente.
